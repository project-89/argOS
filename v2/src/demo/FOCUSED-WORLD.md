# Before Tonight: the focused living-world testbed

Two autonomous people, one apartment, one physical phone. Elaine is getting ready
to meet Alex; Jerry knows her evening plans, not her private messages. A viewer can
change the contact profile, text the phone, or plant an explicitly attributed
thought. No reply, emotion, disclosure, or plot outcome is scripted.

This profile uses the same production Argos cognition, planning, reflection,
memory, narrative inner life and physical execution as the larger apartment demo.
It is not the old offline decision fixture or a custom phone-answering controller.
By default the live focused profile also enables spirits, narrative engine,
evolution, coding daemons and god autopilot. `--core-only` isolates cognition for
diagnosis. Enabling those services is not proof that a generated system has been
accepted or that a long-running world is healthy; inspect the recorded status.
Each new episode has an isolated coding directory. Previous accepted releases
and unfinished jobs are not silently restored into a fresh episode. Library
callers can still deliberately reuse a directory for recovery.

## Run and inspect

```sh
npm run demo:focused:ui -- --no-video
npm run eval:focused:live -- --seconds=120 --core-only --label=core
npm run eval:focused:live -- --seconds=120 --label=full-runtime
npm run eval:focused:live -- --seconds=120 --condition=neutral --label=control
```

The UI waits for **Simulation only** (or Go live if video is enabled). Interactive
episodes never inject the old scheduled cookie text. Only explicit eval runners
send fixed, reported stimuli at 8 and 28 simulated seconds. `eval:focused` without
`--live` tests plumbing only; it is not autonomous-cognition evidence. Evaluations
are deliberately bounded to 30–120 seconds and never call H3.

Each evaluation saves configuration and source fingerprints, bounded runtime
logs, a world snapshot, incremental event/frame journals, cognitive states,
transcript, replay, exact render prompts, screenplay beats and a pre-send
performance map. Phone delivery, notification, reading, appraisal, speech and
outbound delivery remain separate observations. A missing reply is not silently
classified as a deliberate choice. Semantic behavior needs transcript review.

## Repaired boundaries

- Goal deadlines and outcome retention use simulation time, not time spent on
  Ready or paused. Standing communication motivation is not a timed one-off task.
- A deterministic plan/contract can execute steps for the actor's chosen purpose;
  it cannot silently substitute the old schedule after every primitive action.
- Actual attention signals have a bounded, identity-scoped private ledger. A
  repeated buzz preserves an unresolved observation, not message contents. The
  actor can explicitly consider/defer it. A completed read resolves only that
  actor's exact notification, not another unread message or a friend's memory.
- A published success criterion certifies its own canonical outcome. Arriving
  in the kitchen cannot certify a broader investigation or social intention.
- Successful physical pickup records a real hand claim, distinct from inventory.
  Possession alone never makes every carried object visible to the camera.

## Rendering contract

The renderer is a read-only projection of committed events and visible state.
Before issuing a prompt, it budgets complete dialogue and essential pickup/read/
typing gestures against calibrated opening/continuation media durations. It uses
focal shots for phone actions and explicit silence after exact scripted speech.
Overflow is an explicit failure, never truncated words or silently dropped acts.
Thoughts and phone receipts follow that same pre-issued source/media map.

This does not control the provider's chunk duration or guarantee that H3 obeys
the choreography. A materially short chunk reports unavailable alignment; a
repeated version holds the prior source state. Historical recordings without a
performance map retain their old mapping. The eval's immediate offline renderer
acknowledgements test compilation, **not** transport latency or actual video.

The focused camera and physical package currently cover the two established
rooms and initial cast. This is a diagnostic foundation for a growing world,
not yet a demonstrated unbounded prompt-to-world camera or a long-running soak.

World builders also receive a native service inventory from the library. God,
the architect and managed coding workers can distinguish existing cognition,
dialogue, planning and timed execution from generated ECS systems. This prevents
the registry's omission of native services from being presented as missing
functionality; it does not guarantee that every model proposal is sensible or
every build will succeed. `sim.getRuntimeServices()` exposes the same inventory.

Focused evaluations return a nonzero exit status for a reported renderer fault,
while still saving the complete cognition evidence. A clean compilation result
is not a behavioral score or a claim that H3 followed the prompts.
