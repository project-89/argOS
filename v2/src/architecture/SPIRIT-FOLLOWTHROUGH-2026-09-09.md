### Explicit trusted rule restoration

`approveRuntimeRuleDefinitions` and `restoreRuntimeRuleApprovals` are exported
host APIs. Approval definitions must come from a separate trusted host catalogue,
not `snapshot.schema.rules`. The in-memory approval token is non-portable; a
serialized/copied token is not authority. An application may persist approved
definitions separately and explicitly approve that catalogue after restart.

Restoration validates every candidate before granting any: full native shape,
exact digest definition, current numeric capability support and exact spawn-type
dependencies. Unknown/altered/duplicate/private definitions reject the batch.
Enabled flags remain unchanged. Restored effects are immutable; host enable/disable
remains possible. Stop/reset/rewind/task cancellation revoke execution. The legacy
WorldSchema singleton is explicit: restore requires its owning isolated world and
cannot steal another live world's grant. No auto-restore hook is enabled by default.

Snapshot loading now keeps non-base rules ungranted even if their marker was
removed. Impersonating a base rule name is insufficient: the complete pinned
native definition must match. Direct trusted host-defined rules still work.

### Rich generated residents

Optional validated `past` flows through individual and room-content blueprints,
canonical actor creation, private persona and native narrative/identity archive.
Agent component overrides cannot erase the constructor-applied background. Entire
place preflight rejects an invalid final biography before any entity is allocated.
Props/rooms cannot receive actor histories. Existing residents cannot be reseeded.
Authoring instructions describe the field; it remains optional, so a model may
omit it (the live baker did). This is supported private biography authoring, not
a claim that every generated cast has mutually consistent histories.
